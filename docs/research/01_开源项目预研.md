## 0. 结论先行（给 Lead 直接引用）

**Q：有没有能"直接满足全部需求"的开源项目？**
**A：没有。** 截止 2026-10-19，未找到任何开源项目能同时做到「读 Synthesizer V 工程 → 自动得到音素/时间轴 → 映射为口型 viseme → 直接控制 PSD 差分图层 → 离线批量出帧」。最接近的是两个 **闭源免费软件 + 开源插件** 的组合：**YMM4（PSD 立ち絵 + 口パク + まばたき + KuchiPaku 的 .lab→あいうえお口型）** 和 **AviUtl + PSDToolKit（MIT，PSD 直接渲染 + 目パチ + 口パク + Lua 脚本）**，但两者都绑定 Windows GUI 宿主、不读 `.svp`、不自动切表情，不能作为本工具的"现成轮子"直接嵌入。

四条最关键判断：

1. **`.svp` 离线解析拿不到"默认音素"是设计使然，不是文件损坏。** SynthV 的 note 上有两个概念：`Note.getPhonemes()` 只返回**用户手动覆盖**的音素（本工程为空字符串即属正常）；真正的默认发音由 SynthV 内部"歌词→音素转换器（T2P）"按音库词典在宿主内生成，官方文档明确 `SV.getPhonemesForGroup()` / `SV.getComputedAttributesForGroup()` 返回的是**内部 T2P 的输出**（"the output of Synthesizer V Studio's internal text-to-phoneme converter"）。见 [Note 类文档](https://resource.dreamtonics.com/scripting/Note.html)、[SV 类文档](https://resource.dreamtonics.com/scripting/SV.html)。→ **纯离线读 JSON 无法得到默认音素；要在 SynthV 宿主里用官方脚本 API 导出，或自建 G2P。**
2. **官方脚本 API 确实是"能拿到音素"的正路，但只能在 SynthV Studio 2 Pro 里跑。** `getPhonemesForGroup(group)` 返回逐音符的音素串（不直接给每个音素的时间端点）；2.1.1+ 的 `getComputedAttributesForGroup(group)` 进一步返回每个音素的 `symbol / language / activity（辅音强度）/ position（辅音位置）`，是目前最接近"音素时间轴"的官方能力。官方示例仓库 `svstudio-scripts` 为 **Apache-2.0**；社区已有现成脚本 `GroupPhonemes.lua`（**CC0-1.0**）演示如何用这两个 API 导出音素，可直接改写复用。
3. **"歌词/音素 → 口型"这一层有可复用的开源件，但没有"中文+日文混合歌词"的现成品。** 音频驱动侧：**Rhubarb Lip Sync（MIT，1.14.x，2026-06 仍在推送）** 可用 `-r phonetic`（音素模式、语言无关）对日语/非英语音频出 A–H/X 9 种口型 JSON，第三方 2026-01 实测日语可用但只是"近似"；**MFA（Montreal Forced Aligner，MIT）** 可用中/日声学模型做强制对齐拿 phone 级时间作兜底。文本驱动侧：**KuchiPaku（MIT）** 是目前唯一现成的 `.lab（音素标注）→ あいうえお口型时间轴` 自动化工具，但只面向 YMM4、日语音素集。**中文拼音→viseme 的独立开源库：未找到可靠来源**，需自建（可用 `pypinyin`，MIT）。
4. **PSD 这一层"轮子"很足，缺的只是"时间轴驱动 + 批量渲染"。** Python 侧 **psd-tools 1.25.0（MIT）** 可读层树/可见性/合成（1.25 文档明确 composite 能力与限制）；JS 侧 **ag-psd（MIT）** 可读写 PSD。**PSDToolKit（MIT）** 已证明"PSD 直接渲染 + 口パク + 目パチ + 差分"在 Windows/AviUtl 上完全可行，且提供 Lua 脚本形式的口パク控制；**YMM4 原生支持 PSD 立ち絵**并可在"PSD立ち絵素材マネージャー"里指定口パク/まばたき图层。**但"按音轨/音素自动切换 PSD 表情图层"的跨宿主开源项目：未找到。**

### 2.2 对本工程的直接含义

1. `.svp` 是 JSON（社区已有解析器 UtaFormatix3），但**默认音素由音库词典在宿主内生成**，`notes[].phonemes` 为空正是"没有手动覆盖"的正常状态。想拿到"真正会唱的音素"，只有三条路：
   - **A（最准）**：在 SynthV Studio 2 Pro 里跑脚本，用 `getComputedAttributesForGroup` / `getPhonemesForGroup` 导出 JSON/CSV（可基于 CC0 的 `GroupPhonemes.lua` 改）。
   - **B（无宿主）**：自建 G2P（中文 `pypinyin` 声母/韵母 + 日语 kana/romaji 规则 + 手工 `.` 音素串解析）+ 音素→viseme 映射；精度取决于自建词典，但完全离线。
   - **C（音频兜底）**：先渲染/拿到人声 wav，再用 **MFA** 或 **Rhubarb** 做音频侧对齐，绕过 `.svp` 的音素不确定性。
2. 多 take / 多 group 的取舍、tick→秒换算、`"-"` 延音、重叠等属于 `.svp` 语义问题，已在 task-3 的 `svp_probe.py` 中处理；本报告不重复。
3. 官方脚本 API 是 **2.x 文档**；若用户工程是 SV1 格式（`v196` 按 Lead 核实），需确认本机 SynthV 版本能打开并运行对应 API（`getComputedAttributesForGroup` 为 2.1.1+；`getPhonemesForGroup` 更早版本即存在）。**版本适配需实测，未找到"SV1 也有 getComputedAttributesForGroup"的可靠来源。**

### 3.2 这一段的关键结论

- **"音频驱动"和"文本/音素驱动"是两条完全不同的路线**：Rhubarb/uLipSync/Live2D 都是音频驱动（不需要歌词，但对中文/日语的音素精度是"近似"）；KuchiPaku 是音素驱动（需要 `.lab`，但能精确到 あいうえお）；本需求是"从 `.svp` 的音素出发"，**KuchiPaku 的思路（.lab→5 元音口型时间轴）与 PSD 差分选择最契合**，但其宿主绑定不能直接复用，只能借鉴"音素→口型类别→时间轴"的实现方式。
- **中文（普通话）的 viseme 映射没有现成开源库**：检索中只找到 TTS/学术方案（如 PaddleSpeech 类前端）与零散代码，未找到"歌词/拼音→口型差分"的可复用开源项目 → **必须自研映射表**（可基于拼音韵母表 + 日语 5 元音 + 英语 viseme 分类），这一点应在技术方案里明确写为"自研"。
- Oculus/ARKit viseme（15 viseme / ARKit 52 blendshape）是**分类约定**而非工具，可作为 viseme 类别设计的参考，本报告不列为依赖候选。

### 4.2 这一段的关键结论

- **PSD 渲染不需要自研底层**：`psd-tools`（MIT）足以做"逐帧设置可见性 + composite"。**真正的自研点是"帧调度 + 差分组合缓存 + 性能"**（moca.psd 27MB、目标 5800 帧，需要 layer-level 缓存 + 只重绘变化区域，见 task-2 实测）。
- **"PSD 差分自动切换"在日文圈已有成熟工程实现**（PSDToolKit / Syncroh2 / YMM4），但全部是"宿主软件 + 插件"，**没有一个是可嵌入的库**。若用户愿意用现成软件做后期，最省事路线是 YMM4（PSD立ち絵 + KuchiPaku）；若要"自动人物立绘差分选择工具"本身，只能自研"时间轴→图层可见性"这一层，PSD 合成用 psd-tools。
- **图层命名规范**：YMM4 的 `口.a/.i/.u/.e/.o/.0`、PNGAL 的 `eye_open/eye_close/mouth_open/mouth_close`、Syncroh2 的"表情自动检测"都说明**差分图层命名是可约定的**；task-2 的图层清点结果应作为映射表的输入。

## 7. 推荐技术路线（可直接写进最终方案）

### 7.1 三层拆解（与任务要求一致）

**第一层 · 直接可用的轮子（拿来即用，均为宽松许可）**

| 音素→口型参考实现 | `KuchiPaku` | 最新 release | MIT | **只借鉴算法/规则**（.lab→あいうえお），不直接嵌入（YMM4 绑定） |
| 音素导出脚本参考 | `avilesjf/synthv-scripts` 的 `GroupPhonemes.lua` | 最新 | CC0-1.0 | 在 SynthV Pro 里导出 `getComputedAttributesForGroup` 结果 |

**第二层 · 可复用组件（需要改造/裁剪）**

- **UtaFormatix3（Apache-2.0）**：`.svp` → `.ufdata` 的解析路径 + 开放中间格式，可作为"自研 `.svp` 解析器"的对照实现/测试基准（尤其多 track/多 group/tempo）。
- **svstudio-scripts（Apache-2.0）+ 官方脚本 API**：在 SynthV Pro 内导出音素 JSON 的宿主端脚本（本项目"高精度模式"）。
- **PNGAL（Apache-2.0）**：其"PSD 图层→差分素材 / sprite sheet+JSON 导出"与 RIFE 中间帧思路可复用（不做同步这点要避开）。
- **PSDToolKit（MIT）**：若最终选择 AviUtl 生态，可直接用其 Lua 脚本接口做"外部时间轴→口パク/目パチ/差分"；其"PSD 对象 + Lua 控制"是最接近的可编程参考。
- **YMM4/KuchiPaku 链路**：若用户接受"用现成软件出视频"，这是最省成本的人工/半自动路线（`.lab`→KuchiPaku→YMM4）。

**第三层 · 必须自研**

1. **`.svp` → 音符/时间轴/歌词/（可选）音素** 的离线解析与语义处理（多 take、重叠、`"-"` 延音、手工音素串 `.U N cl` 等）——task-3 已给出原型。
2. **中/日/罗马音混合歌词 → 音素 → viseme 映射表**（中文韵母表 + 日语 5 元音 + 英语 viseme 兼容；无现成库）。
3. **逐帧视觉调度器**：viseme 持续/过渡（协同发音）、眨眼随机/乐句触发、表情事件（按标点/音高/手动标记）、多轨优先级。
4. **PSD 差分合成渲染器**：图层可见性组合缓存、只重绘脏区、60fps/5800 帧性能优化（psd-tools 是"读+合成"库，不是渲染引擎）。
5. **配置/覆盖层**：图层名→语义（a/i/u/e/o/n/closed、eye open/half/closed、表情）的可编辑映射，用户工程变化时的健壮性。

### 7.2 三条可选路线与取舍

| 路线 | 组成 | 精度 | 开发量 | 适用 |
|---|---|---|---|---|
| **A. 高精度（推荐默认）** | SynthV Pro 脚本导出音素（CC0 脚本改）→ 自研 viseme/事件 → psd-tools 渲染 → ffmpeg | 最高（用 SynthV 自己的 T2P） | 中（需用户有 SynthV Pro 并打开工程） | 用户本机已有 SynthV Pro（本工程来自 SynthV） |

| **C. 音频兜底/校验** | 人声 wav → MFA（或 Rhubarb）→ phone/口型 → 映射 → 渲染 | 中（歌唱对齐误差） | 中 | 作为 A/B 的交叉校验；或 `.svp` 不可用时 |

## 10. 给最终技术方案的 5 条可直接引用结论

1. **没有端到端开源项目**；最接近的是 YMM4（闭源免费，PSD 立ち絵 + 口パク + まばたき，配合 MIT 的 KuchiPaku 做 .lab→あいうえお）与 AviUtl + PSDToolKit（MIT，PSD 直接渲染 + 目パチ + 可编程口パク），但都不是库、不读 `.svp`。
2. **`.svp` 离线拿不到默认音素是设计使然**：官方脚本 API `getPhonemesForGroup` / `getComputedAttributesForGroup` 才返回内部 T2P 结果（需 SynthV Studio 2 Pro 宿主）；社区已有 CC0 脚本 `GroupPhonemes.lua` 可改造；无宿主时必须自建 G2P（pypinyin + 日语规则）或用 MFA/Rhubarb 从音频兜底。
3. **PSD 合成不需要自研底层**：psd-tools 1.25.0（MIT）即可；自研点是"时间轴→图层可见性 + 组合缓存 + 5800 帧性能"。**psd-tools 对调整层/智能对象/文字层支持有限，moca.psd 必须先做兼容性实测（task-2）。**
4. **歌词/音素→viseme 没有"中日混合"现成库**：Rhubarb 音频驱动（MIT，日语近似可用）、KuchiPaku 音素驱动（MIT，仅日语 5 元音 + YMM4）、MFA（MIT，phone 对齐兜底）；中文 viseme 映射与协同发音规则必须自研。
5. **License 红线**：svp2lab（无 license）、Live2D（专有）、psd2live（GPL-3.0）、YMM4/AviUtl/Syncroh2（闭源免费）不可作为分发依赖；推荐分发链全部落在 MIT/Apache-2.0/BSD-2/CC0 内；用户 PSD 本身"非商用、禁二次配布"，工具输出不得打包分发素材。
