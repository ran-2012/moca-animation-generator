# PSD 差分自动选择 — 端到端可行性原型（task-4）

**结论：可行 ✅** — PSD 差分层可离线提取/缓存（一次 ~20s），逐帧合成 ~1.2ms（992×1400），
按时间轴 24fps 出 demo 视频实际耗时 ≈6× 实时（12s 版 2.3s；真实 SVP 时间轴 24.4s 版 5.0s）；
且用"底板 + 补丁"重建出的画面与 `psd.composite()` **逐像素一致（diff_max=1，>8 的像素占比 0.00%）**。

真实数据链路已打通：`_work/svp/viseme_timeline.json`（60fps、14359 帧、239.3s、8 类 viseme）
→ 采样到 24fps → PSD 差分逐帧合成 → H.264；眨眼/情绪用 `_work/svp/expression_events.json`
里的真实事件（92 次眨眼 + 29 段情绪），找不到时自动退回规则调度。

```
 moca.psd ──psd_diff.py（一次性, ~20s）──► prototype/cache/moca/
                                             base.png（隐藏 口/目/眉/颊 的底板）
                                             mouth_a.png … brow_normal.png（各带 offset）
                                             manifest.json（图层路径/offset/校验数据）
                                                  │
 viseme_timeline.json ──render_demo.py──► DiffComposer（纯 PIL, ~1.2ms/帧）
   （或 --mock）                              │  + 眨眼调度 + 表情切换
                                             ▼
                                        raw RGBA 管道 → ffmpeg(libx264) → demo.mp4
```

> 素材为本项目私有插画，缓存/demo 仅本地自用，勿分发。

## 2. 实测耗时（本机，Windows）

### 2.1 缓存导出（一次性；含 psd-tools 解析 + composite + 像素校验）

| 步骤 | moca_small.psd (921×1300) | moca.psd (2480×3500) |
|---|---|---|
| 打开 PSD | 0.111 s | 0.178 s |
| 导出 25 个差分层 PNG | 0.056 s | 0.099 s |
| 底板 composite（隐藏 4 组） | 2.199 s | 10.722 s |
| 像素级校验（重建 vs composite） | 1.674 s | 8.955 s |
| **合计** | **4.15 s** | **20.53 s**（含校验；`--no-verify` 约 11.2s） |
| 缓存体积（base+25 补丁） | 0.59 MB | **2.06 MB** |

> 瓶颈是 psd-tools 的整图 composite（大图 10.7s），只在首次导出发生；之后渲染完全不碰 PSD。

### 2.2 单帧合成性能（纯 PIL alpha_composite）

| 输出尺寸 | 帧数 | mean | p50 | max | 理论 fps |
|---|---|---|---|---|---|
| 2480×3500（原分辨率） | 50 | **7.86 ms** | 7.84 ms | 8.63 ms | 127 |
| 992×1400（推荐输出） | 50 | **1.14–1.23 ms** | 1.10–1.21 ms | 1.72 ms | ~800–877 |
| 921×1300（小图） | 50 | 1.38 ms | 1.33 ms | 1.87 ms | 723 |

（含 base.copy() + 最多 4 个 alpha_composite；不含 PNG 编码。补丁与 offset 在初始化时按目标
分辨率一次性缩放，加载 992×1400 整套缓存 ~220ms。）

### 2.3 整段 demo 渲染（`prototype/demo.mp4`，992×1400 @24fps、真实时间轴 27.6–52s、586 帧）

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 加载缓存 + 预缩放 | 0.24 s | 一次性 |
| 逐帧合成 | 1.17 s（1.99 ms/帧） | DiffComposer（比 bench 略高：含状态解析/复制） |
| 管道写 ffmpeg / x264 编码 | **3.02 s**（5.15 ms/帧） | 当前瓶颈 |
| ffmpeg 收尾 | 0.09 s | |
| **渲染循环合计** | **4.59 s ≈ 127.7 fps** | = **5.3× 实时** |
| 进程总耗时 | 4.99 s | 含 import/管道探测/写 meta |

（12s mock 版：288 帧，渲染循环 1.98s ≈ 145fps，进程总耗时 2.32s；与真实版同一路径。）

外推：3 分钟歌曲（4320 帧 @992×1400）≈ **30 s** 出片（渲染循环 ~5.3× 实时）；
即使直接渲染 2480×3500 全分辨率，合成侧约 34 s + 编码。作为对比，若每帧都调用 psd-tools
composite（大图 ~8.9s/帧）需要 **~10 小时** —— 离线缓存把渲染从"不可行"变成"秒级"。

## 3. 差分图层清单（manifest.json 内为准确数据）

组定位（用名字 DFS + 路径校验，与 psd-analyst 的 layer_tree_*.json 一致，大小图结构相同）：

| 组 | 路径 | 说明 |
|---|---|---|
| 顔パーツ | `0.3` | 脸部差分层父组 |
| 頬 | `0.3.0.0` | 脸颊 |
| 口 | `0.3.1` | 口型（24 个变体，含 あいうえお 子组 `0.3.1.19`） |
| 目 | `0.3.2` | 眼睛（開き `0.3.2.0` / 閉じ `0.3.2.1`） |
| 眉毛 | `0.3.3` | 眉毛 |

导出 25 层（key / PSD 路径 / 层名）：

| 类别 | key → 路径 |
|---|---|
| 口型 | `mouth/a`→`0.3.1.19.4` あ、`i`→`...19.3` い、`u`→`...19.2` う、`e`→`...19.1` え、`o`→`...19.0` お、`n`→`0.3.1.1` ん、`omega`→`0.3.1.3` ω、`nicco`→`0.3.1.17` にこ、`square`→`0.3.1.13` □、`wa`→`0.3.1.0` わー、`laugh`→`0.3.1.10` はは（`ﾆﾁｬ笑み` 该层不在小图结构内，已跳过） |
| 眼睛 | `open`→`0.3.2.0.2.9` 通常（默认有效可见那张）、`open_alt`→`0.3.2.0.1.11` 通常、`closed`→`0.3.2.1.9` ーー、`closed_smile`→`0.3.2.1.8` にっこり、`closed_shy`→`0.3.2.1.7` ＞＜、`closed_wide`→`0.3.2.1.0` ○○ |
| 眉毛 | `normal`→`0.3.3.0`、`angry`→`0.3.3.1`、`question`→`0.3.3.2`、`surprise`→`0.3.3.3`、`sad`→`0.3.3.4` |
| 脸颊 | `normal`→`0.3.0.0.0`、`blush`→`0.3.0.0.1` 赤面、`deep`→`0.3.0.0.2` 真っ赤 |

- **z-order（底→顶）**：`cheek → mouth → eye → brow`，由 顔パーツ 子组顺序决定（manifest.zorder）。
- 每层导出的 PNG 尺寸 = 图层 bbox，位置 = `layer.offset`（topil 是裁剪图，合成时 `alpha_composite(img, dest=offset)` 贴回画布）。
- **默认可见状态**（导出时记录）：口型 ω、眉毛 怒り、眼睛 通常、脸颊 通常。demo 里显式用 brow=normal（默认 怒り 的表情不适合演示）。

### 像素级校验（为什么敢说"无损分解"）

`psd_diff.py --verify` 会：`参考图 = psd.composite()`；`重建图 = base.png + 默认状态补丁按 z-order 叠加`；
逐像素比较。结果（大小图一致）：

```

diff_mean = 0.0017
pct_pixels_diff_gt8 = 0.000%
verdict = IDENTICAL
```

`--save-verify` 会保存 `verify_default.png`（重建图）和 `verify_diff.png`（差异 ×8 放大图）。

## 4. 时间轴输入（render_demo.py 的 adapter）

默认读 `_work/svp/viseme_timeline.json`；不存在时自动用 mock 时间轴并打印提示。已容错的格式：

```json
{"fps":24, "frames":[{"t":0.0,"viseme":"a"}, {"t":0.12,"viseme":"i"}]}
{"fps":24, "frames":[{"time":0,"vowel":"i","duration":0.12}]}
{"duration":12.3, "segments":[{"start":0,"end":0.12,"viseme":"a"}]}
["a","a","i","i","u"]                       // 每帧一个 viseme
```

viseme 值容错：`a/i/u/e/o`、`あ行` 假名、`ka/shi/tsu` 之类罗马字（取元音）、`N/cl/-/sil` 视为闭口 `n`、
特殊口型 `omega/にこ/□/wa`。未知值回退到 `n` 并计数（写在 meta `missing_state_fallbacks`）。
输出帧率与时间轴帧率解耦：按时间重采样到 `--fps`（**60fps 时间轴 → 24fps 输出已实测**）。

### 4.1 已接入的真实时间轴（svp-analyst 产出）

| 文件 | 内容 |
|---|---|
| `_work/svp/viseme_timeline.json` | `fps=60`、`duration=239.32s`、`frame_count=14359`；`frames[] = {t, viseme, openness, note}`；另有 `notes[]`(655)、`mouth_runs[]`(548)、`stats`、`token_coverage`(100%) |
| `_work/svp/expression_events.json` | `blinks[]`(92，含 t/duration/reason) + `emotions[]`(29，mood/intensity/t_start/t_end) |

viseme 8 类 → PSD 口型层映射（`compose.norm_viseme`）：`a/i/u/e/o` 直接对应；
`closed`（休止）→ `ん`(n)；`n` → `ん`；`f`（本工程仅 13 帧）→ `う`。
采样窗口：`--start 27.6 --seconds 24.4`（Lead 指定的有歌词段落，覆盖 i/e/a/u/o 五元音）。

**眨眼**：优先用真实 `blinks[]`（窗口内 7 次，按 `t/duration` 转帧，实测与视频抽帧一致）；
没有事件文件时退回规则（每 3–5s 一次、闭眼 2 帧）。
**表情/眉毛/脸颊**：优先用真实 `emotions[]` 的 mood 映射
（`intense→怒り眉+赤面`、`bright→通常眉+赤面`、`calm→通常`、`melancholic→悲しみ眉`）；
没有事件文件时退回规则（每 8–12s 轮换一次「驚き/にこ/疑問/悲しみ」）。
`meta.json` 里会写明 `blink_source` / `expression_source` 是 `real` 还是 `rule`。

`--start` 支持 `auto`（默认：自动跳过开头静音，从第一个非 closed 处开始）/ `none`(0) / 具体秒数；
窗口内时间戳会平移到 0，事件也按窗口偏移换算。

> 注意：SVP 的情绪只是弱启发式（由音高/音符密度推断），真实"演技"仍需人工标注；
> 本 demo 用真实事件是为了证明"事件→差分选择"链路成立，不代表最终表情质量。

## 6. 已知限制 / 风险（产品化前要处理）

1. **clipping mask / layer mask 未在真实素材上验证**：本 PSD 的 `clipped=0`、`mask=0`（psd-analyst 统计），
   代码里保留了 `apply_clipping_mask()`（补丁 alpha × base 层 alpha）入口但**未触发过**。若换 PSD 出现
   腮红/腮发被脸部裁剪的层，需在导出阶段对 clipping 层预乘 base alpha，再缓存。
2. **只支持普通像素层**：blend mode ≠ NORMAL、组 opacity、图层样式（描边/阴影）、调整层/矢量层/智能对象
   的渲染效果不会出现在缓存里。本素材差分层全部是 NORMAL/100%，所以无损；换素材需先检查 manifest
   `blend/opacity/skipped`，必要时对差分组整体 composite 而不是取单层（代价：每状态一张补丁）。
3. **z-order 是硬编码的**（cheek→mouth→eye→brow）；PSD 分组顺序变化需改 `manifest.zorder`。
4. **同名层靠启发式选择**：眼睛有多个「通常」（不同子分支），用"祖先全部 visible"挑有效可见层；
   换 PSD 需人工核对 preview。
5. **口型是 viseme→5 元音的启发式映射**，不是音素级 co-articulation。若 SVP 时间轴只给元音/音素，
   本原型能直接吃；若给的是音素（k/s/t 等），映射规则已在 `compose.norm_viseme` 里留了扩展点。
6. **眨眼/表情规则是 demo 调度**，不是最终产品逻辑：产品化建议由 SVP 的音符/乐句边界、重音、休止驱动。
7. **输出背景**：合成图是 RGBA，转 H.264 yuv420p 时 alpha 被丢弃 → demo 背景为黑。正式出片应合成
   到指定背景色/背景图，或输出带 alpha 的中间格式（ProRes 4444 / VP9-alpha / PNG 序列）。
8. **宽高必须为偶数**：libx264+yuv420p 对奇数尺寸报 `-22 Invalid argument`；`render_demo.py` 会自动
   把宽高调成偶数（例如 460×649 → 460×648），README 这里的尺寸都已是偶数。
9. **沙箱环境 temp 目录可能不可写**：ffmpeg 管道探测与 PNG 序列兜底目录都放在 `prototype/_tmp/`
   （系统 temp 不可写时也能跑通 PNG 序列兜底路径，已实测）。
10. **缓存过期**：manifest 记录 PSD 绝对路径与生成时间，但没有哈希；PSD 改动后需手动删
    `prototype/cache/<stem>/` 重新导出（建议产品化加 mtime+size 或 md5 校验）。
11. **时间轴已接入真实 SVP**：`_work/svp/viseme_timeline.json`（60fps）与
    `expression_events.json` 均已实测跑通（`blink_source/expression_source = real`）。
    仍属原型的部分：`closed→ん`、`f→う` 这类 viseme→口型映射是启发式；SVP 情绪是音高弱启发式；
    多音轨/和声取哪条由 svp-analyst 的规则决定（本 demo 用其默认主轨）。

## 7. 关键实现决策（供最终方案参考）

- **底板 + 补丁** 而不是"每帧 psd.composite()"：这是性能从 ~8.9s/帧 → 1.2ms/帧的关键（~7000×）。
- **像素级自校验**：用默认可见状态重建并与 PSD 自带 composite 对比，diff_max≤2 才算缓存可信；
  这让"z-order/裁剪/offset 贴错"这类错误在导出时就能暴露，而不是等到出片。
- **分辨率预缩放**：补丁和 offset 在 Composer 初始化时一次性缩放到输出尺寸，逐帧零缩放零解码。
- **时间轴与渲染解耦**：adapter 容错 + 按时间重采样，时间轴 JSON 换 schema 不用改渲染代码。
- **ffmpeg 管道 + 兜底**：先 1 帧探测 stdin 管道可行性，失败自动切 PNG 序列再编码；两种模式都实测通过。
- **缓存极小**（大图 2.06MB / 小图 0.59MB）：差分层都是小 bbox PNG，适合随项目分发给渲染端/前端。
